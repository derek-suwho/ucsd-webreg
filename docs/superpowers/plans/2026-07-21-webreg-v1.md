# UCSD WebReg Replacement v1 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Public course-planning site with classic WebReg workflow — client-side search, multi-schedule planner, calendar/list/finals views, conflict detection — fed by a background scraper of UCSD's public Schedule of Classes.

**Architecture:** npm-workspaces monorepo. `apps/web` (Next.js App Router) serves UI + thin JSON API over shared packages. `apps/worker` scrapes SoC → Postgres and regenerates a per-term catalog JSON snapshot that clients download once (ETag) and run search/planner logic on locally. `packages/planner` and `packages/search` are pure TS (zero I/O).

**Tech Stack:** TypeScript, Next.js 15 (App Router), Prisma + PostgreSQL 16, NextAuth v5 (Google), Zustand, @dnd-kit/core, Tailwind CSS v4, cheerio (HTML parsing), Vitest, Playwright, Railway.

**Spec:** `docs/superpowers/specs/2026-07-21-webreg-replacement-design.md` — read it first.

## Global Constraints

- Node ≥ 20. TypeScript strict mode everywhere.
- Keep files under 500 lines (project rule) — split before exceeding.
- Zod validation at every system boundary: API route input, scraped-data normalize, env vars.
- Never commit secrets or `.env`. `archive/capture/` stays gitignored.
- No default Tailwind palette colors (no `blue-600`/`indigo-500`); custom brand tokens only. No `transition-all`.
- Every page shows "Not affiliated with UC San Diego" disclaimer in footer.
- Scraper politeness: ≤4 concurrent requests, ≥200ms spacing, User-Agent `webreg-revival/1.0 (contact: dsu87654321@gmail.com)`.
- Times stored as minutes-from-midnight integers. IDs: Course `FA26:CSE:110`, Section `FA26:CSE:110:A01`.
- Commit messages: concise, no AI attribution.
- Invoke `frontend-design` skill before frontend tasks (16–21).

```ts
export function parseTime(time: string): number {
  const [hour, minute] = time.slice(0, -1).split(':').map(Number)
  const am = time.endsWith('a')
  return (hour === 12 ? (am ? 0 : 12) : am ? hour : hour + 12) * 60 + minute
}

export function parseTimeRange(range: string): { start: number; end: number } {
  const [start, end] = range.split('-')
  return { start: parseTime(start), end: parseTime(end) }
}

const DAY_RE = /^(?:(?:Sun|T[uh]|[MWFS])+)$/
export function parseDays(s: string): string | null {
  if (s === 'TBA') return null
  if (!DAY_RE.test(s)) throw new RangeError(`Bad days: "${s}"`)
  return s
}

const UNIT_RE = /\( (\d+)(\.5)?(?: [/-](\d+)(?: by (\d+)(\.5)?)?)? Units\)/
export function parseUnits(courseInfo: string): { from: number; to: number; inc: number } {
  const m = courseInfo.match(UNIT_RE)
  if (!m) throw new SyntaxError(`Missing units in: ${courseInfo}`)
  const from = Number(m[1]) + (m[2] ? 0.5 : 0)
  const to = m[3] ? Number(m[3]) : from
  const inc = m[4] ? Number(m[4]) + (m[5] ? 0.5 : 0) : 1
  return { from, to, inc }
}
```

Parsing rules (port of `archive/reference/uxdy-scheduleofclasses-scrape.ts` lines 359–732; that file is the authority when in doubt):
- Rows live under `#socDisplayCVO .tbrdr` tbody. Row classes: `.sectxt` (purple section row, 13 cells; 10 cells when time is a colspan TBA; 6 when cancelled), `.nonenrtxt` (white row: exams AND extra meetings of multi-lecture sections, 10 cells; 5 when cancelled; 2 cells = a note row), `.crsheader` (4 cells = course header; 3 cells = reduced header preceding a red note).
- Seats cell: `Unlim` → available/capacity null; `FULL Waitlist(17)`-style (regex `/\((\d+)\)/` on a cell containing `FULL`) → available 0, waitlisted 17; else integer.
- `days === 'Cancelled'` → cancelled row. Exam rows have a date (`MM/DD/YYYY`) in the section-code cell (`includes('/')`).
- Unknown row shape → **throw** (strict parser; caller quarantines department).

### Task 5: Normalizer (ParsedRow[] → NormalizedCourse[])

**Files:**

**Interfaces:**
- Produces:
```ts
export type NormalizedMeeting = { type: string; days: string | null; startMin: number | null;
  endMin: number | null; building: string | null; room: string | null }
export type NormalizedExam = { type: 'FI' | 'MI'; date: string; startMin: number; endMin: number;
  building: string | null; room: string | null }
export type NormalizedSection = { id: string; sectionCode: string; familyCode: string;
  registrationNumber: number | null; instructor: string | null; capacity: number | null;
  available: number | null; waitlisted: number | null; isCancelled: boolean; note?: string;
  meetings: NormalizedMeeting[]; exams: NormalizedExam[] }
export type NormalizedCourse = { id: string; subject: string; number: string; title: string;
  unitsFrom: number; unitsTo: number; unitsInc: number; restriction: string[]; note?: string;
  sections: NormalizedSection[] }
export function normalizeDepartment(rows: ParsedRow[], termId: string): NormalizedCourse[]
```
Rules:
- Section rows following a course row belong to it. Family grouping: `familyCode` = leading letters of sectionCode (`A01`→`A`; numeric `001`→`001`).
- Enrollable rows (have registrationNumber + sectionCode) become `NormalizedSection`s. Non-enrollable weekly rows (lecture without reg number, extra multi-lecture meetings) attach their meeting to **every enrollable section of the same family** (that is what enrolling means: you get the shared meetings). If a family has NO enrollable child (e.g. lecture A00 itself has the reg number), the A00 row is the enrollable section.
- Dated exam rows (`examDate` set) attach as `exams` to every enrollable section of the family. Weekly meeting types map through MeetingType enum; unknown → `'OT'` + collect warning (function returns `{courses, warnings: string[]}` — adjust signature: `normalizeDepartment(...): { courses: NormalizedCourse[]; warnings: string[] }`).
- Instructor: first instructor string or null.

import NextAuth from 'next-auth'
import Google from 'next-auth/providers/google'
import { prisma } from '@webreg/db'

export const { handlers, auth, signIn, signOut } = NextAuth({
  providers: [Google],
  session: { strategy: 'jwt' },
  callbacks: {
    async jwt({ token, profile }) {
      if (profile?.email) {
        const user = await prisma.user.upsert({

    },
  },
